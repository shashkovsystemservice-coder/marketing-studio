# Navigator — критическая редакция 13 диагностических вопросов (v0.2)

Дата: 2026-11-15. Статус: ПРОЕКТ, не утверждён, не внедрён. Основание: карточки v0.1 и определения элементов RC3, проверенные в GitHub. Это не проверка всех 50 отношений онтологии.

## Результат критического прохода
- В v0.1 T4 явно соединял сегментацию и проверку спроса; T2, T6, T8, T9, T11, T12 также включали несколько операций в вопрос/индикатор. Для минимального ядра ниже выбран один наблюдаемый признак на вопрос.
- В v0.1 в карточках перечислены несколько RC3-элементов, но не все непосредственно проверяются. В v0.2 каждому базовому вопросу присвоен один ПЕРВИЧНЫЙ элемент. Остальные связи сохраняются в v0.1 как контекст для будущих дополнительных вопросов, не как измеренные компетенции.
- Формат ответа «Да / Частично / Нет / Не знаю / Не применимо» остаётся качественным самоотчётом. При «Частично» не следует выводить, какой именно компонент отсутствует, без дополнительного уточнения.
- Один ответ не даёт оценки всей земли. Отсутствие практики не доказывает причину бизнес-проблемы.

## Интерпретация и следующий шаг по каждой карточке

### T1 / T1.14
**Вопрос:** Отслеживает ли ваша компания изменения внешних условий, которые могут повлиять на покупателей или спрос?

**При «Нет» или «Частично»:** Если нет — определить 2–3 изменения, значимых для основного рынка; не делать вывод об экономике или регулировании по отдельности.

**При «Да»:** респондент заявляет наличие именно этой практики; не оценивать результативность.

**При «Не знаю»:** данных для самооценки нет, не приписывать положение на числовой шкале.

**При «Не применимо»:** отдельный статус, не приравнивать к «Не знаю» или «Нет»; допускается необязательное пояснение.

## Ограничения и обязательная проверка до релиза

1. T1.14 «Неопределённость» является состоянием, а не способностью отслеживать внешние изменения. Связь T1 носит контекстный характер; требуется подобрать в RC3 более прямой элемент либо обозначить компетенцию как надстройку над несколькими элементами. НЕЛЬЗЯ считать T1.14 достаточным основанием.
2. T8.07 «Готовность платить» — объект исследования, а не процесс. Вопрос оценивает заявленную практику исследования готовности платить, а не саму готовность или её уровень.
3. T12.18 «Способность реализации» шире назначения ответственного. Базовый вопрос проверяет только один признак.
4. T13.01 «Данные» шире использования сведений. Нельзя по ответу оценить качество данных.
5. Для T2 вопрос о лице, принимающем решение, нельзя автоматически считать проверкой всех ролей покупателя, плательщика и пользователя.
6. Требуется отдельная экспертиза релевантности к B2B/B2C, производству, услугам, компаниям с длинным и коротким циклом покупки. Не все вопросы одинаково уместны всем компаниям.
7. Нужно проверить естественность ответов «Да / Частично / Нет» и не допускать двойных отрицаний. При необходимости дать примеры без навязывания ответа.
8. Дополнительные вопросы по задачам должны выбираться через явную матрицу «задача → компетенция → RC3», а не из произвольного списка земель. Приоритеты и целевые профили НЕ утверждены.
9. Не использовать условные числа .83/.52/.18 как обоснованную измерительную шкалу. Вопросы v0.2 ещё не проверены на пользователях.
10. До отдельного согласования НЕ заменять v0.1, НЕ менять HTML и НЕ деплоить на Vercel.
