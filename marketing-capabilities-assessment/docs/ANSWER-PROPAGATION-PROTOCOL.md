# Протокол проверки связей и распространения ответов — v0.1

## Проверенные входные данные
Каноническая RC3: 185 элементов и 50 отношений. Машинный проход нашёл упоминания отношений у 143 элементов; 42 пока без распознанных отношений. В 25 отношениях хотя бы одна сторона не разрешена в канонические ID. Это **не** доказательство отсутствия связи: в RC3 присутствуют внешние объекты, диапазоны и иные выражения.

## Модель ответа (проект)
- `question_id`: версия и идентификатор вопроса.
- `subject_id`: о какой компании/продукте/рынке идёт речь.
- `context`: сегмент, география, период, объект анализа.
- `answer_value`: типизированное значение (один вариант, несколько, шкала, да/нет/неизвестно).
- `claims[]`: утверждения с `element_id`, `predicate`, `value`, `evidence_type`, `confidence`.
- `relation_triggers[]`: идентификаторы применимых отношений RC3 и основания для последующей проверки.

## Правила распространения
1. Ответ может создавать **несколько явно обоснованных утверждений** о разных объектах.
2. Отношение RC3 может инициировать новый вопрос о связанном объекте.
3. Связь сама по себе не доказывает истинность нового утверждения.
4. Никакой автоматической передачи баллов между связанными элементами.
5. Учитывать ограничения применимости, направление, временной статус, контекст и носителя отношения.
6. «Не знаю» фиксирует отсутствие ответа, а не отсутствие способности.
7. Доказательство, самоотчёт и экспертная оценка должны храниться отдельно.

## Пример для проверки (не утверждённый вопрос)
Вопрос: «Какие роли участвуют в принятии решения о покупке?»
Прямые объекты: T3.07, T3.08 и релевантные роли T2.
Возможные следующие проверки: критерии выбора T3.09 через REL.005, участие акторов в buying center T3.08 через REL.006.
Ответ не даёт права автоматически оценивать все роли и всю территорию T3.

## Необходимые проверки перед алгоритмом
- Вручную разобрать 25 частично неразрешённых отношений.
- Отделить ссылки на внешние объекты от канонических ID.
- Проверить правила диапазонов и неоднозначные форматы Domain/Range.
- Выделить типы отношений, допускающие логический вывод, отдельно от отношений, допускающих только навигацию.
- Определить для каждого элемента применимость, диагностируемый конструкт и необходимое свидетельство.

**Статус:** исследовательский протокол, не утверждённая шкала маркетинговых способностей.
