Дата: 2026-11-15. Статус: проект для методической проверки, НЕ внедрён и НЕ утверждён.

## Основание и границы
- Пять задач и их существующие области взяты из marketing-capabilities-assessment/prototype/index.html.
- 13 базовых вопросов и первичные RC3-коды — из RC3-DIAGNOSTIC-QUESTIONS-REVIEW-v0.2.md.
- Дополнительные вопросы НОВЫЕ, сформулированы как проект на основе названий и определений элементов RC3. Это не готовые валидированные вопросы, не доказанная зависимость задачи от компетенции и не автоматический вывод всей сети RC3.
- Пользователь самостоятельно оценивает компетенции компании. Никаких документов, регистрации, обязательных дополнительных инструментов.

## Гипотеза сценария
13 базовых вопросов (общая карта) + до 3 дополнительных вопросов выбранной задачи. Максимум 16 ответов; это предложение, требующее теста на время и утомляемость. Сначала можно задать вопросы по задаче, затем предложить общую карту — порядок ещё не утверждён. Не задавать дважды одинаковую способность. Дополнительные вопросы выводят более узкие компетенции и не должны пересчитывать автоматически всю землю.

## Правила результата
1. Для каждой способности сохранять question_id, primary_rc3_id, territory_id, task_id, answer, optional_detail и статус уверенности в выводе. Не превращать субъективный ответ в измеренный факт.
2. «Да» = заявленная практика; «Частично» = частичная заявленная практика; «Нет» = не заявлена; «Не знаю» = недостаточно сведений; «Не применимо» = отдельная категория.
3. Приоритет в задаче означает значимость для дальнейшей проверки, а не доказанную причину проблемы. Без обоснованной шкалы не вычислять числовые разрывы и «идеальный» профиль.
4. Выводы формулировать на уровне конкретной способности: ответ → интерпретация → следующий самостоятельный шаг. Не отправлять посетителя в другой продукт.
5. Демо-ответы не должны маскироваться под ответы реальной компании.
6. Дать итоговую карту и 2–3 наиболее полезных рекомендации, а также возможность раскрыть подробности всех ответов.

## Критические нерешённые вопросы
- Для задачи «Как увеличить прибыль?» маркетинговых компетенций недостаточно для анализа финансовой прибыли: нужно честно обозначить границу либо переформулировать задачу.
- Для задачи «Почему клиенты уходят?» базовая T11.14 про стадии до покупки слабо подходит для удержания. Основной смысл дают дополнительные вопросы T11.17 и T12.16; базовые приоритеты нужно пересмотреть.
- Дополнительные вопросы могут быть двусмысленны: например «оценивает ли спрос» требует простого определения для посетителя.
- Перечисление RC3-элементов подтверждает терминологическую трассируемость, но ещё не подтверждает причинные отношения. До внедрения проверить отношения RC3 и экспертно обосновать значимость каждого вопроса для задачи.
- Проверить различия B2B/B2C, товар/услуга, регулярная/разовая покупка; не требовать сегментации, продажной воронки и иных практик там, где они неприменимы.
- Вариант «общая диагностика» ещё не утверждён как отдельный вход; не менять интерфейс до решения.
