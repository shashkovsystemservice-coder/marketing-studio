# Navigator — 13 базовых карточек самодиагностики RC3 × MASTER

Рабочий проект v0.1, 15.11.2026. Не внедрено в сайт. По одной минимальной оцениваемой практике на территорию; НЕ полная оценка территории.

## Общие правила

Ответы для всех карточек: «Да, систематически» / «Частично или иногда» / «Нет» / «Не знаю» / «Не относится». Ответ «да» означает самоотчёт, а не доказанную результативность. «Не знаю» не получает среднего балла; «не относится» исключается из оценки только после контекстной проверки. При отрицательном ответе рекомендация описывает следующий шаг, а не установленную причину проблемы.

Карточка выбирается по задаче, не все 13 обязательны. Точное соответствие process_id MASTER и семантика REL/MEC должны пройти построчную верификацию по первоисточникам перед программной реализацией. Ниже ссылки REL/MEC — кандидаты для трассировки, а не сертификат соответствия.

## 1. T1 — Отслеживание обязательных изменений

- **Предмет RC3:** T1.09
- **Оцениваемая практика:** Отслеживание обязательных изменений (проектная операционализация; не онтологическая сущность).
- **Вопрос:** Перед важными рыночными решениями вы проверяете, не изменились ли правила и ограничения, влияющие на ваше предложение?
- **Задачи:** Выход на рынок.
- **Связи для проверки:** MEC.002.
- **Подсказка MASTER:** MASTER: ветвь исследования рынка и R5; конкретный gate для регулирования не подтверждён.
- **Если «нет»:** допустимо заключить лишь «практика не заявлена». **Следующий шаг:** Определить применимые требования и назначить регулярную проверку изменений.
- **Если «частично»:** выяснить, какой компонент выполняется и какой отсутствует.
- **Если «не знаю»:** предложить выяснить, выполняется ли эта практика, без отрицательного балла.
- **Если «да»:** не считать эффективность доказанной; при необходимости проверить использование результата в следующем решении.

## Проверки до реализации

1. Сверить каждый REL/MEC с направлением, domain/range и условием применения в каноническом RC3.
2. Проставить точный process_id и gate_id MASTER только там, где это подтверждено исходной карточкой, не подменять предположением.
3. Отдельно спроектировать уточняющие вопросы, которые различают конкурирующие объяснения; не добавлять их автоматически всем.
4. Для задачи «прибыль» явно ограничить результат маркетинговыми факторами; нельзя диагностировать прибыль без финансовых данных.
5. Протестировать на B2B, B2C, портфеле продуктов, новом бизнесе, «не знаю», «не относится» и противоречивых ответах.
